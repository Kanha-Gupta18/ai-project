# ThermalGuard implementation plan

## Purpose

This plan describes how the working project is built and checked. It also records the current state so that unfinished work is not confused with completed work.

## Working assumptions

- The local dataset file remains outside version control unless its license and size make distribution appropriate.
- The installed Python environment will be used if it satisfies the project dependencies. The project will not download another Python release only to match an exact version.
- Complete measurement profiles are independent operating sessions and must stay in one data partition.
- Validation MAE is the primary model-selection metric because an error in degrees Celsius is easy to interpret.
- The final test set is used only after the model and feature set have been selected.
- The interface is a demonstration tool, not a motor protection or control system.

## Section 4: model development

Status: complete.

Feature sets:

1. Controller signals: ambient, coolant, motor speed, torque, d-q voltage, d-q current, plus derived current magnitude, voltage magnitude, and coolant minus ambient temperature.
2. Enhanced sensors: all controller features plus stator yoke, stator tooth, and stator winding temperatures.

Candidate models:

- Mean baseline
- Ridge regression
- Histogram Gradient Boosting regression
- XGBoost regression

Work:

- Fit each candidate on the training profiles.
- Evaluate each model and feature-set combination on the same validation profiles.
- Compare MAE first, then use RMSE, R², tolerance accuracy, complexity, and reproducibility as supporting evidence.
- Select one combination before opening the final test results.

Verification:

- Every candidate uses the same profile partitions.
- Preprocessing is fitted with training data during model selection.
- The comparison table is generated from saved metrics rather than typed separately.
- Enhanced Histogram Gradient Boosting has the best validation MAE at 4.61°C.

## Section 5: final evaluation and explanation

Status: complete.

Work:

- Refit the selected pipeline on the combined training and validation profiles.
- Evaluate once on 14 untouched test profiles.
- Calculate MAE, RMSE, R², percentage within ±5°C, and mean bias.
- Review residual patterns and errors for each profile.
- Calculate permutation importance on a documented test sample.

Verification:

- Final test MAE is 5.60°C, RMSE is 7.36°C, and R² is 0.856.
- The tolerance accuracy is 54.4% and mean bias is -0.34°C.
- The report identifies uneven profile performance, including the weakest profiles.
- Importance results are presented as predictive influence, not causal proof.

## Version-control routine

Each meaningful, verified change should form one focused commit. Before committing:

1. Review the changed files.
2. Run the smallest relevant checks, followed by the full test suite when shared behavior changes.
3. Confirm generated artifacts are intentional and large raw data is not staged.
4. Write a direct commit message that describes the observable change.
5. Push only after the local commit is verified.

## Definition of done

A fresh user can follow the README, prepare the dataset, run the tests, reproduce the experiment, inspect the reported results, and launch the Streamlit application. The submission report and repository must describe the same final system.
